# Comparison and export reference

Telryn evaluates a candidate against a recorded queue run. A comparison uses
disjoint historical shifts that start fresh, a single combined exception-count
hurdle, and per-shift operating limits. Keep configuration, rule source and
cutoff evidence stable while reviewers hold a packet.

When the export includes a named tuning shift, supply its eligible membership.
Telryn excludes a required shift if either membership lists any of the same
requests. When tuning data is kept elsewhere, the lead must verify that its
cases are disjoint from the held-out population.

## Definition

The version 1 TOML format is illustrated by
[`examples/refunds/comparison.toml`](../examples/refunds/comparison.toml).
File paths may be absolute or relative to the definition. `--export` can point
to an independently produced snapshot.

| Field | Meaning |
| --- | --- |
| `schema` | Integer format version, currently `1`. |
| `export`, `grades` | Cutoff export and optional initial-grade JSON. |
| `required_shifts`, `tuning_shifts` | Held-out shift IDs and any excluded tuning IDs. |
| `minimum_additional_exceptions` | Nonnegative integer hurdle across the required shifts. |
| `rubric`, `rubric_question`, `evidence_window_hours` | Versioned rubric, blind question, and admissible evidence window starting at cutoff. Use cutoff as the evidence time when grading the exact cutoff snapshot. |
| `workload_method` | Human-readable description of how case time estimates were obtained. |
| `grading_budget`, `cross_checks_per_side` | Maximum packet rows and requested controls per side across this comparison. |
| `live`, `candidate` | Selector source `file`, rule `version`, and declared `tie_break`. Python uses `function`. SQLite uses `engine = "sqlite"` and `required_inputs`. |
| `shifts.<shift>` | Candidate slot `capacity` and scheduled `staff_minutes`. Supply exactly one policy per required shift. |

A Python selector is a trusted function `select(batch, capacity) -> list[str]`.
The batch contains request dictionaries with an `id` and the exported
decision inputs. It carries no rubric grades, observed outcomes, staffing
estimates, or evidence references. Return ordered, unique, eligible IDs.
Returning fewer picks is permitted and visible in the report. An otherwise
valid candidate that exceeds its capacity triggers a hold. Both rules must
apply the tie-break named in the definition. Choose deterministic selectors
and make the source file self-contained apart from the standard library so the
recorded SHA-256 covers the user-supplied rule. Your local Python process
executes the selector with its existing permissions.

## Cutoff export

The [bundled snapshot](../examples/refunds/cutoff.json) was generated by the
standalone SQLite app. The root object has `schema: 1` and a `shifts` object
keyed by shift ID.

| Export field | Example source |
| --- | --- |
| `cutoff` | ISO 8601 timestamp with offset for the historical run. |
| `membership.source`, `membership.ids` | A reference to an independently recorded eligible queue and its complete ID list. |
| `requests.<id>.revision`, `known_at`, `inputs` | The exact source revision, when it was available, and its cutoff decision inputs. Reserve the field `id` for Telryn. Use availability time even when a correction has an earlier effective date. |
| `requests.<id>.evidence` | Permitted references to exact evidence revisions for the rubric. |
| `requests.<id>.minutes` | `null` for unknown time or `{lower, upper, basis}` in whole minutes. Use `observed` for a point value and `estimated` for a supported range. Omit an unknown estimated upper bound or use `null`. |
| `capacity`, `live_version`, `tie_break`, `actual` | Historical limits, rule identity, stable tie-break identifier, and recorded picks in final slot order. |
| `mandatory`, `overrides` | IDs requiring review under the policy and the ordered records explaining historical interventions. Use an empty list for a known absence. |

An `include` override with `request` applies to either rule. It appends a missing
request and, when capacity is exhausted, displaces the weakest selected request
outside the protected set of earlier includes. A `swap` replaces the selected
`replace` ID with `request` in the same slot when the replacement is eligible,
absent, and the incumbent was not protected by an include. An `unresolved`
override carries a `reason` and prevents scoring. Mandatory coverage remains a
separate check. Document which deterministic behavior reflects your queue.

Missing membership, material cutoff revisions, uncertain overrides, or a
live replay divergence make the affected shift **Not replayable**. Cutoff
timestamps compare instants with their UTC offsets and retain all fractional
second digits, including nanoseconds. A revision exactly at cutoff qualifies.
The same precision applies to both endpoints of the grading window. Use
`Z` or a numeric UTC offset with whole seconds. Missing ranking inputs
accessed directly on cutoff rows also block only that shift. Invalid
selectors still return an execution error. A valid shift with a
confirmed operational veto can still determine **Hold** when another shift is
missing. Run `python3 -m telryn qualify --case membership` for an example where
all recorded winners match but the export is incomplete.

## Grading and recovery

Initial grades use [this JSON shape](../examples/refunds/known-grades.json).
A grade needs the frozen rubric, matching exact evidence references, an
`evidence_at` timestamp inside the window, and `shared_sources: true`.
Evidence produced solely by an incumbent-triggered intervention leaves the case
unknown. When an archived grade identifies a non-shared or out-of-window source,
a packet also excludes any current evidence bundle for that case containing the
same exact reference. Supply an independent, admissible bundle in a new
comparison if one is available. Reviewers use the same admissible sources and window for both groups.

Cross-checks are drawn from available accepted grades on each changed side and
take priority within the frozen packet budget. The report records checks still
owed if the budget is smaller than the required controls. Useful unknowns fill the remaining slots while the initial count range spans the
hurdle or required shift coverage is incomplete. If the range lies wholly on one
side of the hurdle, the packet contains only the required controls. Reassess
the frozen plan if a disputed control reopens the range. Any returns that are still needed after the budgeted rows
are exhausted leave the decision open. Reviewers should disclose when they
already know which requests changed. Record this with
`refresh --reviewer-unblinded` on the return. Reviewers may leave `grade` blank or enter
`meets`, `outside`, or `insufficient`.

Each row ID may appear once per returned CSV, including rows left blank.
A duplicate rejects the entire file. An unchanged return in a later file is
idempotent. The default identity uses its
normalized grade and minutes. Supply `refresh --review-id NAME` for independent
reviews with identical content. Keep that ID on retries. Reusing the same ID
with changed contents fails. Mixed answers, including a definitive grade and
`insufficient`, leave the row unknown and require an independent adjudication.
A definitive return after an `insufficient` adjudication reopens the dispute
on that evidence. Any required control stays pending until the conflict is
resolved.

The lead report and JSON output show the row ID and current review set for a
dispute. Record the adjudication against that set so a stale decision cannot
silence a newer return:

```sh
python3 -m telryn refresh runs/tuesday/report.html --adjudicate ROW_ID outside "Independent review of the same evidence" --review-set REVIEW_SET --minutes 2
```

A saved report from v0.3.0 or earlier remains readable. Browsers show the
historical verdict embedded at publication. Current `explain --require-shadow`
withholds approval because the saved report lacks the per-request timestamps
needed to repeat the corrected cutoff checks. Run `compare` on the original
export and issue the new packet before resuming grading, qualifying a pilot,
or recording a new shadow trial. Old packet IDs belong to the original report.

`explain` uses the report's embedded evidence snapshot and works after the
source app has stopped. Refresh takes an advisory lock and atomically replaces
the report on the local filesystem. Retain the lock file while refreshes may
run. Telryn creates the grading CSV with owner-only read and write permissions.
Keep the original blank packet for another partial return. Treat the
report, source exports, working directories, and returned packets as sensitive.
Default reports use case references, and the analyst should keep raw customer
messages out of inputs. Apply retention to all copies. If evidence or a grade
must be erased, withdraw affected artifacts and generate a new comparison with
the remaining admissible material. Loss of a material cutoff input can make a
shift unreplayable. Loss of a grade can widen the range.

### Check a weekly proposal before running a trial

The saved HTML and a plain `explain` show the verdict from the frozen evidence. When the candidate came from a weekly audit, the JSON result identifies this as `weekly_source.status = "historical_snapshot"`. Use both flags in an automated gate that expects a weekly proposal.

```sh
python3 -m telryn explain RUN/report.html --require-shadow --require-weekly-source --format json
```

In the team's trust store, the gate checks the signed comparison evidence against its latest revision and the weekly audit against the revision that generated the candidate. A successful gate returns `weekly_source.status = "current"`. Retain its `comparison_id` and `decision_revision` when starting the trial. New weekly-proposal shadow observations must supply both values. If the held-out grades change before the observation arrives, investigate and qualify a new trial. Preserve the original revision on the recorded observation.

A weekly grade correction invalidates the old proposal for future gated actions. Regenerate the proposal from the updated weekly report, then run the held-out evaluation again. If another copy of a comparison has advanced, use the latest saved report. Existing identical shadow returns on the latest comparison are idempotent, including when the originating weekly audit has since advanced. Pilot benchmarks on weekly proposals require current evidence. Weekly proposal comparisons from v0.5 can still be read as history. Recreating a live gate requires a replay against a signed weekly proposal.

## CLI exit codes

| Code | Meaning |
| --- | --- |
| `0` | Requested artifact or explanation delivered. With `--require-shadow`, the recommendation is **Try in shadow**. |
| `1` | Shadow gate withheld approval or a qualification case failed. |
| `2` | Execution or input error, including a stale source revision, missing trust store, or missing required weekly provenance. |
| `130` | Interrupted. |

Use `--format json` with `compare`, `explain`, or `refresh` for machine-readable
output. Treat report production and recommendation as separate checks in
automation. The historical bounds cover the accepted grades and speak to
exception review coverage. Estimating losses avoided or customer outcomes
requires further evidence.

## Preflight for ordinary CSV exports

Run `python3 -m telryn preflight INTAKE.toml --out CUTOFF.json`. Use the
[worked manifest](../examples/support-qa/intake.toml) to map local CSV headers.
Preflight needs no selector code. It checks structure, source reconciliation,
cutoff availability, and recorded policy evidence. A ready result still
requires replay of the actual picks. An independently sourced list that
happens to contain the same IDs as the selected list requires operator
confirmation of completeness.

| Manifest field | Meaning |
| --- | --- |
| `schema` | Intake format version `1`. |
| `columns` | Optional aliases for `id`, `slot`, `revision`, `known_at`, `evidence`, `cohort`, `lower_minutes`, `upper_minutes`, and `time_basis`. Use `eligible_id`, `picks_id`, or `cutoff_id` for source-specific ID columns. Other unmapped names use their logical headers. |
| `inputs` | Logical ranking field to numeric CSV column. Use finite values and stable score precision. |
| `shifts.<shift>` | Relative or absolute paths for `eligible`, `picks`, and `cutoff_inputs` CSVs, plus `cutoff`, `capacity`, `live_version`, `tie_break`, `membership_source`, `mandatory`, and `overrides`. Use empty lists for a verified absence of mandatory cases or overrides. |

CSV and JSON ranking inputs must retain their value when normalized. Common
decimal scores such as `0.1` are supported. If a fractional value would round
to a different decimal or underflow to zero, Telryn reports the precision
loss. Use a documented integer scale or a string-aware selector when more
precision is required.

The eligibility CSV contains IDs and comes from a separate authoritative source.
Recorded picks use consecutive slot numbers starting at 1. The cutoff CSV has
one row per eligible ID with the actual revision, its availability timestamp,
and ranking fields. Optional columns carry one exact evidence reference, a
cohort, and whole-minute workload estimates. Use the full JSON export contract
when a case needs multiple evidence references or nonnumeric ranking inputs.

`preflight --format json` reports the first gap and how to capture its source
per shift. It exits 0 when ready, 1 when any shift needs evidence, and 2 for
an invalid manifest or output error. When ready, writing the JSON is optional.

### Reuse the mapping across cutoffs

The original single-file intake format remains supported. For a reusable
mapping, put `schema`, `columns`, and `inputs` in the intake file and omit
`shifts`. Supply `--batches BATCHES.toml` with a separate file containing
`schema = 1` and `shifts`. CSV paths in that mode are relative to the batch
manifest. The output JSON still feeds the existing `compare --export` path.
See the [handoff walkthrough](support-qa.md#hand-the-next-cutoff-to-another-analyst).

## SQLite selectors

Set `engine = "sqlite"`, `file` to a UTF-8 SQL file, `version` and
`tie_break` to their recorded values, and `required_inputs` to the logical
input keys the query needs. The required keys must have a value for every
eligible case. Keep rule filters, ranking, and stable tie-breaks in the query.
`engine = "python"` is the default and retains the original Python contract.

```sql
SELECT id
FROM requests
ORDER BY json_extract(inputs, '$.risk') DESC, id ASC
LIMIT :capacity
```

Telryn runs one read-only query in a new in-memory SQLite database exposing
`requests(id TEXT, inputs TEXT)`. `inputs` is the cutoff input object as JSON.
Supported queries can use ordinary read-only SQL, CTEs, and a bounded set of
deterministic SQLite functions, including JSON extraction, common text and
numeric functions, and ranking window functions. The query returns one
column named `id`, with a deterministic order and no duplicates or foreign
IDs. The report retains the exact query hash and SQLite runtime version in
its embedded evidence. Review SQL as part of the comparison definition and
verify any manual reviewer substitutions through the ordinary override log.

Declare every ranking field in `required_inputs`. Integer values in those
fields, including nested values, must fit SQLite's signed 64-bit range.
An out-of-range value makes that shift **Not replayable**, since SQLite can
round distinct JSON integers to the same score. Python selectors retain the
exact integer from a JSON export. For SQL rules that already rank textual
identifiers, preserve the identifiers as strings in the source export.

## Cap serious cases losing review

A comparison can add a `[serious]` table with `max_lost`, `rubric`,
`rubric_question`, and an optional `grades` JSON file in the existing
version 1 grade format. The rubric must differ from the primary rubric.
Both use the same admissible cutoff evidence. An exclusion on an evidence
bundle applies to both grades.

Only cases the live rule selected and the candidate dropped count toward the
limit. The lower bound counts accepted serious cases. The upper bound also
counts unresolved serious cases. Incomplete shift coverage leaves the
combined upper bound unknown. A lower bound above the limit supports
**Hold** once required controls are confirmed. **Try in shadow** needs a
complete upper bound within the limit. Improvements elsewhere cannot cancel
a serious loss. The report lists confirmed and unresolved cases beside the
scheduled reviewer hours.

The ordinary and serious questions can share a case in the single CSV. Each
has its own opaque row ID, grade, and adjudication history. Serious unknowns
that could change the decision take priority after cross-checks within the
shared grading budget. When the serious question is included, the report
flags that a reviewer familiar with its selection rule can infer side.

## Record a completed shadow trial

Run `python3 -m telryn record-shadow REPORT OBSERVATIONS.json`. The report must
support a shadow trial when a new observation is recorded. A repeated identical
import is safe. An existing trial ID with changed contents is rejected.

Use the [observation example](../examples/support-qa/shadow-observations.json).
Supply `schema: 1`, the frozen `comparison_id`, a unique `trial_id`, an
offset-aware `observed_at`, and a `lead_decision` with `action` and `note`.
The allowed actions are `adopt`, `revise`, `hold`, and `continue`. Each
entry in `batches` names a replayable `reference_shift` and lists the
observed candidate `picks` in order. Each pick has an ID, a cohort, and
optionally whole `minutes` recorded by the reviewer. Missing minutes stay
unmeasured. Use the same cohort definition as the historical export. Remove
unlisted fields before import, including transcript text. The report records
the decision revision that qualified the trial. For weekly proposals this must match the `decision_revision` captured at trial start.

Telryn writes observations into the existing report atomically and leaves the
grading CSV as issued. It compares observed case mix, volume, and recorded
workload with the named historical batch. Those differences inform the lead's
decision. The import does not schedule reviews or change live routing.


## Assess a matched pilot record

Run `python3 -m telryn benchmark REPORT PILOT.json --format json`. The
[version 1 example](../examples/support-qa/pilot-record.json) uses the saved
report’s `comparison_id` and `decision_revision`, the UTC calendar `decision_date`, a `comparator` label,
`evidence` of `synthetic` or `observed`, and a positive
`material_minutes_saved`. Optionally enter `policy_changes_last_year`. Use
nonnegative whole minutes for each effort phase in `baseline` and `telryn`.
The decision date must be on or after every replayed cutoff's UTC date.
Telryn reviewer minutes must cover the grading and cross-check minutes already
logged in the report. Adjudication minutes must cover the logged adjudication
time. Add separately measured or previously untimed work to the matching phase.

The recorded `matched` conditions and the lead’s `equally_supported` judgment
are operator attestations. Telryn verifies the comparison identity and grade revision, then checks
that the required shifts replay and cross-checks are complete. Timing and
payback remain unqualified without all matching conditions and an equally
supported assessment. When there are positive recurring savings, time-based
payback is the rounded-up number of changes to recover any incremental setup
minutes. The annual-cadence field compares that number with the recorded
preceding-year count.

A lead may separately report serious misses overlooked by the comparator.
Each ID must match a confirmed serious case losing review in the saved Telryn
report. This finding can qualify on a matched comparison even when the two
decisions had different support. The command prints an assessment and leaves
the existing report and grading packet intact. See the [measurement protocol](evaluation.md#record-the-outcome-of-a-matched-benchmark).

A complaints report built from the combined shortlists of two discovery methods can support a head-to-head comparison. A proposed routing change needs an audit probability sample from the weekly queue. Telryn checks the signed report’s population basis before issuing a candidate.

# Comparison and export reference

Telryn evaluates a candidate against a recorded queue run. A comparison uses
disjoint historical shifts that start fresh, a single combined exception-count
hurdle, and per-shift operating limits. Keep configuration, rule source and
cutoff evidence stable while reviewers hold a packet.

## Definition

The version 1 TOML format is illustrated by
[`examples/refunds/comparison.toml`](../examples/refunds/comparison.toml).
File paths may be absolute or relative to the definition. `--export` can point
to an independently produced snapshot.

| Field | Meaning |
| --- | --- |
| `schema` | Integer format version, currently `1`. |
| `export`, `grades` | Cutoff export and optional initial-grade JSON. |
| `required_shifts`, `tuning_shifts` | Held-out shift IDs and any excluded tuning IDs. |
| `minimum_additional_exceptions` | Nonnegative integer hurdle across the required shifts. |
| `rubric`, `rubric_question`, `evidence_window_hours` | Versioned rubric, blind question, and admissible evidence window starting at cutoff. Use cutoff as the evidence time when grading the exact cutoff snapshot. |
| `workload_method` | Human-readable description of how case time estimates were obtained. |
| `grading_budget`, `cross_checks_per_side` | Maximum packet rows and requested controls per side across this comparison. |
| `live`, `candidate` | Selector source `file`, Python `function`, rule `version`, and declared `tie_break`. |
| `shifts.<shift>` | Candidate slot `capacity` and scheduled `staff_minutes`. Supply exactly one policy per required shift. |

A selector is a trusted Python function `select(batch, capacity) -> list[str]`.
The batch contains request dictionaries with an `id` and the exported
decision inputs. It carries no rubric grades, observed outcomes, staffing
estimates, or evidence references. Return ordered, unique, eligible IDs.
Returning fewer picks is permitted and visible in the report. An otherwise
valid candidate that exceeds its capacity triggers a hold. Both rules must
apply the tie-break named in the definition. Choose deterministic selectors
and make the source file self-contained apart from the standard library so the
recorded SHA-256 covers the user-supplied rule. Your local Python process
executes the selector with its existing permissions.

## Cutoff export

The [bundled snapshot](../examples/refunds/cutoff.json) was generated by the
standalone SQLite app. The root object has `schema: 1` and a `shifts` object
keyed by shift ID.

| Export field | Example source |
| --- | --- |
| `cutoff` | ISO 8601 timestamp with offset for the historical run. |
| `membership.source`, `membership.ids` | A reference to an independently recorded eligible queue and its complete ID list. |
| `requests.<id>.revision`, `known_at`, `inputs` | The exact source revision, when it was available, and its cutoff decision inputs. Reserve the field `id` for Telryn. Use availability time even when a correction has an earlier effective date. |
| `requests.<id>.evidence` | Permitted references to exact evidence revisions for the rubric. |
| `requests.<id>.minutes` | `null` for unknown time or `{lower, upper, basis}` in whole minutes. Use `observed` for a point value and `estimated` for a supported range. An estimated upper bound may be `null`. |
| `capacity`, `live_version`, `tie_break`, `actual` | Historical limits, rule identity, stable tie-break identifier, and recorded picks in final slot order. |
| `mandatory`, `overrides` | IDs requiring review under the policy and the ordered records explaining historical interventions. Use an empty list for a known absence. |

An `include` override with `request` applies to either rule. It appends a missing
request and, when capacity is exhausted, displaces the weakest selected request
outside the protected set of earlier includes. A `swap` replaces the selected
`replace` ID with `request` in the same slot when the replacement is eligible,
absent, and the incumbent was not protected by an include. An `unresolved`
override carries a `reason` and prevents scoring. Mandatory coverage remains a
separate check. Document which deterministic behavior reflects your queue.

Missing membership, material cutoff revisions, uncertain overrides, or a
live replay divergence make a shift **Not replayable**. A valid shift with a
confirmed operational veto can still determine **Hold** when another shift is
missing. Run `python3 -m telryn qualify --case membership` for an example where
all recorded winners match but the export is incomplete.

## Grading and recovery

Initial grades use [this JSON shape](../examples/refunds/known-grades.json).
A grade needs the frozen rubric, matching exact evidence references, an
`evidence_at` timestamp inside the window, and `shared_sources: true`.
Evidence produced solely by an incumbent-triggered intervention leaves the case
unknown. Reviewers use the same admissible sources and window for both groups.

Cross-checks are drawn from available accepted grades on each changed side and
take priority within the frozen packet budget. The report records checks still
owed if the budget is smaller than the required controls. Useful unknowns fill
the remaining slots. Any returns that are still needed after the budgeted rows
are exhausted leave the decision open. Reviewers should disclose when they
already know which requests changed. Record this with
`refresh --reviewer-unblinded` on the return. Reviewers may leave `grade` blank or enter
`meets`, `outside`, or `insufficient`.

An identical returned answer is idempotent. A disagreement makes the grade
unknown pending review. A second reviewer can adjudicate through the team's
existing process. Record that decision locally:

```sh
python3 -m telryn refresh runs/tuesday/report.html --adjudicate ROW_ID outside "Independent review of the same evidence" --minutes 2
```

`explain` uses the report's embedded evidence snapshot and works after the
source app has stopped. Refresh takes an advisory lock and atomically replaces
the report on the local filesystem. Retain the lock file while refreshes may
run. Keep the original blank packet for another partial return. Treat the
report, source exports, working directories, and returned packets as sensitive.
Default reports use case references, and the analyst should keep raw customer
messages out of inputs. Apply retention to all copies. If evidence or a grade
must be erased, withdraw affected artifacts and generate a new comparison with
the remaining admissible material. Loss of a material cutoff input can make a
shift unreplayable. Loss of a grade can widen the range.

## CLI exit codes

| Code | Meaning |
| --- | --- |
| `0` | Requested artifact or explanation delivered. With `--require-shadow`, the recommendation is **Try in shadow**. |
| `1` | Shadow gate withheld approval or a qualification case failed. |
| `2` | Execution or input error. |
| `130` | Interrupted. |

Use `--format json` with `compare`, `explain`, or `refresh` for machine-readable
output. Treat report production and recommendation as separate checks in
automation. The historical bounds cover the accepted grades and speak to
exception review coverage. Estimating losses avoided or customer outcomes
requires further evidence.
